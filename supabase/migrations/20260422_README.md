# Supabase Advisor Findings — Remediation Migrations

Run these in order against the Supabase SQL editor (or via the migration
pipeline). All are idempotent.

## P0 — Security (run these first)

### 1. `20260422_p0a_rls_hardening.sql`
- Enables RLS on every public table missing it
- Drops every `USING (true) WITH CHECK (true)` policy (truly permissive)
- Adds baseline authenticated-only policies where none remain
- Fixes: `rls_disabled_in_public`, `policy_exists_rls_disabled`, `rls_policy_always_true`

### 2. `20260422_p0b_storage_bucket_hardening.sql`
- Drops permissive `public` role policies on `storage.objects` for the photos bucket
- Adds authenticated-only SELECT + owner-folder INSERT/UPDATE/DELETE
- **Partial** fix for `public_bucket_allows_listing` — the bucket itself is still public so existing `getPublicUrl` links keep working
- Full resolution requires switching the app to signed URLs (see `P3` section below)

### 3. MANUAL: Enable leaked-password protection
- **Where:** Supabase Dashboard → Authentication → Policies → **Password Security**
- **Action:** toggle on **"Check against leaked passwords"**
- **Fixes:** `auth_leaked_password_protection`
- One click. No SQL.

## P1 — Hardening

### 4. `20260422_p1_function_search_path.sql`
- Pins `search_path = pg_catalog, public` on every plpgsql/sql function in public
- Defends SECURITY DEFINER functions from schema-shadowing attacks
- Fixes: `function_search_path_mutable`

## P2 — Performance

### 5. `20260422_p2a_missing_fk_indexes.sql`
- Creates `ix_fk_<table>_<column>` on every foreign-key column without a covering index
- Fixes: `unindexed_foreign_keys`

### 6. `20260422_p2b_duplicate_indexes.sql`
- Drops `idx_diagnostics_date` and `idx_diagnostics_zone` (duplicates of `_created_at` and `_zone_id`)
- Fixes: `duplicate_index` on `public.diagnostics`

### 7. `20260422_p2c_rewrite_auth_uid_policies.sql`
- Rewrites every policy that calls `auth.uid()` / `auth.role()` / `auth.jwt()` directly to use the `(select ...)` init-plan form
- Fixes: `auth_rls_initplan`

### 8. MANUAL: Auth DB connections — percentage mode
- **Where:** Supabase Dashboard → Project Settings → Database → **Connection Pooling** / **Auth Connections**
- **Action:** switch "Auth DB Connections" from an absolute value to a **percentage** (recommended: 30–40%)
- **Fixes:** `auth_db_connections_absolute`
- One dropdown. No SQL.

## Not yet addressed (intentional)

### `multiple_permissive_policies`
Too domain-specific to auto-remediate — requires reviewing each affected
table's policy intent. Recommend tackling table-by-table after P0/P1/P2
are in.

### `unused_index`
Some unused indexes back rare-but-critical report queries. Needs manual
review; no auto-drop.

### Bucket flip to private (`storage.buckets.public = false`)
Requires client-side migration from `getPublicUrl` → `createSignedUrl`
across every code path that displays a photo. Separate P3 project.

## Verification

After running P0/P1/P2, paste this into the SQL editor and expect zero rows:

```sql
-- 1. Any public table with RLS still off:
SELECT c.relname FROM pg_class c JOIN pg_namespace n ON n.oid = c.relnamespace
WHERE n.nspname = 'public' AND c.relkind = 'r' AND NOT c.relrowsecurity;

-- 2. Any public policy still blanket-true:
SELECT tablename, policyname FROM pg_policies
WHERE schemaname = 'public'
  AND ((qual = 'true' AND with_check = 'true')
    OR (qual = 'true' AND with_check IS NULL)
    OR (qual IS NULL AND with_check = 'true'));

-- 3. Any public function without a pinned search_path:
SELECT p.proname FROM pg_proc p JOIN pg_namespace n ON n.oid = p.pronamespace
WHERE n.nspname = 'public' AND p.prokind = 'f'
  AND p.prolang IN (SELECT oid FROM pg_language WHERE lanname IN ('sql', 'plpgsql'))
  AND (proconfig IS NULL OR NOT (proconfig::text LIKE '%search_path%'));

-- 4. Any FK column without a leading-column index:
SELECT cls.relname AS table_name, att.attname AS column_name
FROM pg_constraint c
JOIN pg_namespace n   ON n.oid = c.connamespace
JOIN pg_class cls     ON cls.oid = c.conrelid
JOIN LATERAL unnest(c.conkey) WITH ORDINALITY AS k(attnum, ord) ON true
JOIN pg_attribute att ON att.attrelid = c.conrelid AND att.attnum = k.attnum
WHERE c.contype = 'f' AND n.nspname = 'public' AND k.ord = 1
  AND NOT EXISTS (
    SELECT 1 FROM pg_index idx
    WHERE idx.indrelid = c.conrelid AND idx.indkey[0] = att.attnum
  );
```
