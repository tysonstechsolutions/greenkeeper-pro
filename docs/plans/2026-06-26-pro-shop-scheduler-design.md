# Pro Shop Scheduler — design

_2026-06-26_

## Goal

Build hours/days scheduling for the **pro shop & golf ops** staff (rec aids +
golf ops assistants) — a group distinct from the greens crew. Modeled directly
on Tyson's "June 2026 Pro Shop Schedule" PDF.

The schedule is **mostly consistent through the season**: each person has a
standing weekly pattern. A new month is generated by stamping those patterns
across the dates, then tweaked for time-off/holidays. Tyson can also change the
schedule on the go (someone wants a day off after being scheduled) and have the
AI propose who covers.

## The PDF model

- Monthly calendar grid (Sun–Sat). Each day has **two stacked groups**:
  - **OUT = Outside Staff** → **Rec Aids** (Joe, Bart, Devin, Aniya, Tony, Colin)
  - **IN = Inside Staff** → **Golf Ops Assistants** (DJ, Marty, Mike)
- Each assignment is `start–end Name` in 24h (e.g. `0800-1400 Joe`,
  `0600-1300 DJ`). Inside opens early (0530/0600); Outside starts 0800; close
  ~2000.
- Highly repetitive week to week; exceptions are handwritten (e.g. "NO ANIYA",
  "Aniya out 21–25 Jun", Bart covering).

Position ⇒ group: `rec_aid → outside`, `golf_ops_assistant → inside`.

## Data model (4 new tables, public schema, RLS = all authenticated)

- **`pro_shop_staff`** — lightweight, NO logins.
  `id, full_name, position ('rec_aid'|'golf_ops_assistant'), default_group
  ('outside'|'inside'), availability_text, availability jsonb, phone, is_active,
  sort_order, notes, created_at, updated_at`.
  `availability` JSON = standing weekly pattern:
  ```json
  { "weekly": { "sun": {"works":true,"group":"outside","start":"08:00","end":"14:00"},
                "mon": {"works":false}, ... },
    "notes": "free text" }
  ```
- **`pro_shop_schedules`** — one row per month.
  `id, month (date, 1st of month, UNIQUE), title, status ('draft'|'published'),
  notes, created_at, updated_at`.
- **`pro_shop_shifts`** — the assignments.
  `id, schedule_id fk, staff_id fk, shift_date, group ('inside'|'outside'),
  start_time, end_time, source ('template'|'ai'|'manual'), note, created_at`.
- **`pro_shop_time_off`** — `id, staff_id fk, start_date, end_date, reason,
  created_at`. Drives "NO ANIYA" annotations + re-cover.

## Engine (client-side, deterministic — `schedule-engine.ts`)

- `expandMonth(staff[], year, month, timeOff[])` → proposed shifts: for each date,
  for each active person whose weekly pattern works that weekday, emit a shift
  (group/start/end from the pattern), unless they're off (time-off range).
- `coverageGaps(shifts, date)` → warns when a day has no opener/closer or an
  empty group.
- This means **Generate works with zero AI** and is reproducible.

## AI (edge function `pro-shop-ai`, Claude, same pattern as `ai-assistant`)

Single function, `action` switch. Returns structured JSON the client applies
(review before save). All have a manual fallback so nothing hard-depends on AI.

1. `parse_availability` — `{name, position, text}` → `{weekly, notes}`. Turns
   "Joe works Mon/Wed/Fri 8–2 outside, off Tuesdays, can close weekends" into the
   weekly pattern. Manual fallback: 7-row availability editor.
2. `cover_change` — `{date, staffName, reason, dayGrid, availableStaff}` →
   `{changes:[{action,staffName,start,end,group,note}], explanation}`. Manual
   fallback: pick a person + times by hand.

## UI — `/pro-shop-schedule` (surfaced in BOTH views via /more)

- Month picker + calendar grid rendered like the PDF (OUT block over IN block,
  `time–time Name`).
- **Generate month** (deterministic), **Publish**, tap a shift to edit/remove,
  add shift, **Day off / change** (AI cover), per-person **Edit availability**
  (manual editor + talk-to-AI).
- Coverage warnings banner.
- The 9 staff also appear read-only in a **"Pro Shop & Golf Ops"** card on
  `/staff` (both views) — satisfies "both" storage without logins.

## Monthly reminder

On **Publish**, upsert a `calendar_events` row (category `deadline`,
`"Update Pro Shop Schedule — <next month>"`, dated ~5 days before month-end) so
it surfaces on `/calendar`.

## Seed (from the June PDF)

- 9 staff (Colin O'Neill has an empty pattern until set — he's not on the June
  sheet). Each existing person's `availability.weekly` derived from the PDF so a
  regenerated month reproduces it.
- June 2026 `pro_shop_schedule` (published) + its `pro_shop_shifts` stamped from
  the patterns, with Aniya time-off 21–25 and Bart cover, matching the sheet.

## Scope guard (YAGNI)

No payroll/hour totals, no per-employee logins, no swap-approval workflow.
Just generate, tweak, re-cover.
