# Building the GreenKeeper Pro Android APK

This guide walks you through turning the deployed PWA at
`https://vmgc-greenkeeper.vercel.app` into a sideloadable Android APK using
PWABuilder. It takes about 15 minutes of clicking. No Android Studio, no Java,
no command line.

> **Read this whole thing once before you start.** You'll know what's coming.

---

## What we're building

A **Trusted Web Activity (TWA)** — a thin Android app that opens your deployed
PWA full-screen, with no browser URL bar, no tabs, no bookmarks. Looks and
feels like a native app. Updates automatically whenever you redeploy the
website. Works offline for cached pages (via the existing service worker).

---

## Prerequisites (already done)

- [x] PWA is deployed at `https://vmgc-greenkeeper.vercel.app`
- [x] Manifest exists at `/manifest.json` with all icon sizes
- [x] Service worker (`/sw.js`) generated by Serwist on production builds
- [x] Middleware updated so `/manifest.json`, `/sw.js`, `/icons/*`, and
      `/.well-known/*` are publicly accessible (no auth redirect)
- [x] Placeholder `/public/.well-known/assetlinks.json` committed

---

## Step 1 — Deploy the latest code to Vercel

The middleware fix and the placeholder assetlinks file need to be live before
PWABuilder can read them.

```
git add -A
git commit -m "Add TWA support: public .well-known + manifest, assetlinks placeholder"
git push
```

Wait for Vercel to finish deploying (~2 min). Then sanity-check in a private
browser window:

- `https://vmgc-greenkeeper.vercel.app/manifest.json` → should return the JSON,
  not redirect to the login page
- `https://vmgc-greenkeeper.vercel.app/.well-known/assetlinks.json` → should
  return the placeholder JSON

If either redirects to `/pin-login`, the middleware fix didn't deploy. Stop
and fix before continuing.

---

## Step 2 — Generate the APK on PWABuilder

1. Go to **https://www.pwabuilder.com**
2. Paste `https://vmgc-greenkeeper.vercel.app` into the URL box and click
   **Start**
3. PWABuilder scores your PWA. You should see a high score on Manifest and
   Service Worker. If it complains about anything, fix it and redeploy before
   continuing.
4. Click **Package For Stores** → **Android**
5. In the Android options dialog, fill in:
   - **Package ID:** `com.vmgc.greenkeeper`
     (this must match what's in `public/.well-known/assetlinks.json` — don't
     change it unless you also update that file)
   - **App name:** `VMGC GreenKeeper`
   - **Launcher name:** `VMGC` (keep it short — Android truncates around 12
     chars)
   - **App version:** `1.0.0`
   - **App version code:** `1`
   - **Host:** `vmgc-greenkeeper.vercel.app`
   - **Start URL:** `/dashboard`
   - **Theme color / Background color:** leave as detected (`#1B4332`)
   - **Display mode:** `standalone`
   - **Orientation:** `portrait`
   - **Signing key:** choose **"Create new"** (PWABuilder will generate one
     and include it in the download)
6. Click **Download Package**

You'll get a ZIP file containing:
- `app-release-signed.apk` — the file you install on your phone
- `app-release-bundle.aab` — ignore, only needed for Play Store
- `signing.keystore` — **KEEP THIS FILE SAFE.** You need it to sign future
  updates. If you lose it, every user has to uninstall and reinstall.
- `assetlinks.json` — the real file with the correct SHA256 fingerprint

---

## Step 3 — Update assetlinks.json with the real fingerprint

PWABuilder's download includes an `assetlinks.json` with the correct
`sha256_cert_fingerprints` value baked in from the keystore it just generated.

1. Open the `assetlinks.json` from the PWABuilder download
2. Copy the entire contents
3. Replace the contents of `public/.well-known/assetlinks.json` in this repo
   with what you just copied
4. Commit and redeploy:

```
git add public/.well-known/assetlinks.json
git commit -m "TWA: add real assetlinks.json fingerprint from signing key"
git push
```

5. Wait for Vercel. Verify in a private window that
   `https://vmgc-greenkeeper.vercel.app/.well-known/assetlinks.json` returns
   the new fingerprint (not the placeholder).

**Why this matters:** Android's Digital Asset Links verifier fetches this file
the first time the TWA launches. If it matches the APK's signing key, Android
hides the URL bar and trusts the app. If it doesn't match, you get a "running
in Chrome" bar across the top forever.

## Step 4 — Install on your phone

1. Copy `app-release-signed.apk` to your Android phone. Easy options:
   - Email it to yourself and open the attachment
   - Upload to Google Drive and download on the phone
   - USB cable: drag the file into the phone's Download folder
2. On the phone, open the file (tap the notification or find it in Files)
3. Android will warn: **"For your security, your phone is not allowed to
   install unknown apps from this source."** Tap **Settings**, enable
   **"Allow from this source"** for whichever app you're installing from
   (Files, Drive, Gmail, whatever), then go back
4. Tap **Install**
5. Launch **VMGC** from your home screen

**First launch test:** The app should open directly into the login screen
with **no browser URL bar at the top**. If you see a URL bar, the asset links
verification failed — go back to Step 3 and double-check that the fingerprint
in `public/.well-known/assetlinks.json` matches the one PWABuilder generated.

---

## Step 5 — Save the keystore somewhere you won't lose it

Put `signing.keystore` (from the PWABuilder zip) somewhere permanent:
- A password manager's secure notes attachment (1Password, Bitwarden)
- An encrypted cloud folder
- A backup drive

**If you lose this file**, you cannot ship updates to the same "app" — every
install will have to be uninstalled and reinstalled from scratch, and they
can't carry over the same package ID cleanly.

Also save:
- The keystore password
- The key alias and key password
(PWABuilder shows these during download — screenshot them.)

## Updating the app later

The beauty of a TWA: since it loads your deployed website, **you don't need
to rebuild the APK every time you push a code change.** Users get updates
automatically the next time they open the app and the service worker syncs.

You only need to rebuild the APK when you want to change:
- The app name or launcher icon
- The package ID (don't)
- Android-level permissions or deep links
- The version displayed in Android's app list

To rebuild: repeat Step 2 on PWABuilder, but upload your saved
`signing.keystore` instead of creating a new one. Increment the version code.

## Troubleshooting

### "URL bar shows at the top of the app"
The asset links file isn't verified. Check in order:
1. `https://vmgc-greenkeeper.vercel.app/.well-known/assetlinks.json` is
   publicly reachable and returns valid JSON
2. The `sha256_cert_fingerprints` value matches what PWABuilder used when
   signing (re-download from PWABuilder to double-check)
3. The `package_name` in the file matches the APK's package ID exactly
4. Force-close the app, go to Android **Settings → Apps → VMGC → Storage →
   Clear Data**, relaunch. Android caches the verification result.

### "PWABuilder score is low on Manifest"
Usually means it couldn't fetch the manifest. Check that `/manifest.json`
doesn't redirect to the login page when logged out (Step 1 sanity check).

### "PWABuilder can't find a service worker"
The service worker is only generated on production builds, not dev. Make sure
you're pointing PWABuilder at the deployed Vercel URL, not `localhost`.

### "Android says 'app not installed'"
You probably have an old version with the same package ID installed from a
previous build. Uninstall it first, then install the new one. Or increment
the version code in PWABuilder and rebuild.

### "Installation blocked by Play Protect"
Expected for a sideloaded app. Tap **Install anyway** / **More details** →
**Install without scanning**. This warning goes away if you ever publish to
the Play Store.
